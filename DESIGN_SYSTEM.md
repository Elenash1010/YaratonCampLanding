# Design System сайта «Яратон»

Версия: 1.1  
Статус: рабочий стандарт  
Область применения: основной сайт, страница сведений, новые посадочные страницы и интерфейсные блоки

## 1. Назначение

Этот документ фиксирует единый визуальный и интерфейсный язык сайта «Яратон». Он нужен, чтобы новые страницы, секции и компоненты выглядели как части одного продукта, оставались понятными для родителей и не требовали заново изобретать оформление.

При расхождении между старым кодом и этим документом для новой разработки приоритет имеет Design System. Существующие страницы приводятся к стандарту постепенно, без массовой переделки вне задачи.

## 2. Идея бренда

### Образ

«Яратон» — безопасное, живое и современное место семейного отдыха и детского развития. Визуальная система соединяет два ощущения:

- доверие, порядок и компетентность для родителей;
- энергию, тепло и радость для детей.

### Три принципа

1. **Доверие прежде декора.** Цены, даты, условия, документы и контакты должны считываться быстрее декоративных элементов.
2. **Живые эмоции через контент.** Атмосферу создают реальные фотографии, тексты и небольшие цветовые акценты, а не пёстрый интерфейс.
3. **Спокойная основа, яркое действие.** Большая часть интерфейса белая и тёмно-синяя; красный используется для главного действия и редких смысловых акцентов.

### Характер

Дружелюбный, уверенный, ясный, деятельный. Не канцелярский, не «детсадовский», не премиально-холодный.

## 3. Дизайн-токены

Источник токенов в коде — `styles/tokens.css`. Новые значения сначала добавляются туда, затем используются в компонентах. Не следует вводить локальные оттенки, радиусы и тени без обоснованного нового состояния.

### Цвета

| Роль | Токен | Значение | Применение |
|---|---|---:|---|
| Фон страницы | `--bg` | `#FFFFFF` | Основной фон |
| Поверхность | `--paper` | `#FFFFFF` | Карточки, панели, модальные окна |
| Основной текст | `--text` | `#000000` | Текст с максимальной читаемостью |
| Заголовки / brand navy | `--heading`, `--primary` | `#233B59` | Заголовки, навигация, важные значения |
| Вторичный синий | `--primary2` | `#6290C3` | Поддерживающие акценты, графика |
| Светло-синий фон | — | `#EEF4FF` | Вторичные кнопки, выбранные вкладки, метки |
| Светло-синяя граница | — | `#C4D5EC` | Контур вторичных элементов |
| Главный красный | — | `#FF1D25` | Верх градиента основного CTA |
| Глубокий красный | — | `#C1272D` | Низ градиента CTA, смысловые акценты |
| Успех | `--leaf` | `#2DBD7E` | Только подтверждённое успешное состояние |
| Информация | `--sky` | `#3D8BFF` | Информационные статусы |
| Внимание | `--sun` | `#FFD166` | Предупреждения без ошибки |
| Доп. акцент | `--vio` | `#7C5CFF` | Редкие категорийные метки |

Правила:

- красный CTA должен быть главным цветовым акцентом в пределах экрана;
- тёмно-синий передаёт структуру и доверие, красный — действие и энергию;
- цвет не является единственным носителем смысла: статус сопровождается текстом или иконкой;
- для обычного текста на белом использовать чёрный или тёмно-синий; серый допустим только для вторичной информации;
- не использовать чистый красный для больших фоновых площадей и длинного текста;
- декоративные зелёный, жёлтый и фиолетовый не смешивать в одном компоненте.

### Градиенты

Основной CTA: `linear-gradient(180deg, #FF1D25, #C1272D)`.

Градиент допустим для основной кнопки и брендовой графики. Для карточек, полей и информационных панелей предпочтительны однотонные поверхности. Не создавать новые градиенты без отдельной роли.

### Типографика

Основной шрифт — **Montserrat** с резервом `system-ui, -apple-system, "Segoe UI", Arial, sans-serif`. Разрешённые начертания: 400, 500, 600, 700.

| Стиль | Размер | Начертание | Межстрочный интервал | Применение |
|---|---|---:|---:|---|
| Display / H1 | `clamp(28px, 3.6vw, 42px)` | 400 | 1.18 | Один главный заголовок страницы |
| H2 | `clamp(24px, 3.2vw, 38px)` | 600 | 1.12 | Заголовок секции |
| H3 | `18px` | 600 | 1.2 | Заголовок карточки или группы |
| Lead | `clamp(15px, 1.5vw, 18px)` | 400 | 1.5 | Вводный абзац |
| Body | `16px` | 400 | 1.5 | Основной текст |
| Small | `13–14px` | 400–600 | 1.4 | Подписи и метаданные |
| Caption | `11–12px` | 400–600 | 1.35 | Только служебные пояснения |

Правила:

- на странице только один `h1`; уровни заголовков не пропускаются;
- заголовки короткие, без точки в конце;
- капслок не используется для абзацев и кнопок;
- жирность 700 применять для цен, ключевых значений и коротких акцентов, но не для больших массивов текста;
- минимальный размер содержательного текста — 14 px, служебной подписи — 11 px;
- ширина длинного текстового блока — ориентировочно 60–75 знаков в строке.

### Сетка и интервалы

- максимальная ширина контента: `1160px`;
- боковые поля контейнера: `20px` на обычных экранах, `14px` до 420 px;
- базовый шаг: `4px`;
- предпочтительная шкала: `4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80px`;
- внутри одного компонента чаще использовать 8–16 px, между смысловыми группами — 16–24 px, между секциями — 48–80 px;
- выравнивать элементы по общей сетке; случайные значения допустимы только для оптической коррекции.

### Радиусы, границы, тени

| Роль | Значение |
|---|---:|
| Карточка | `10px` |
| Кнопка | `8px` |
| Метка / chip | `8px` |
| Полностью круглый элемент | `999px`, только для точки, аватара или настоящей pill-формы |
| Обычная граница | `1px solid rgba(11,15,20,.12)` |
| Обычная тень | `0 8px 18px rgba(11,15,20,.08)` |
| Поднятая поверхность | `0 14px 28px rgba(11,15,20,.12)` |

Тени обозначают уровень поверхности, а не служат украшением. Вложенные элементы не должны каждый иметь одинаково сильную тень.

## 4. Логотип и айдентика

- использовать только подготовленные SVG из `assets/logos/`;
- не менять пропорции, внутренние цвета и градиенты логотипа через CSS;
- сохранять свободное поле вокруг знака не меньше визуальной высоты одной буквы логотипа;
- размещать логотип на спокойном однотонном фоне с достаточным контрастом;
- не добавлять к логотипу тень, обводку, поворот или внешнее свечение;
- для шапки и подвала использовать предназначенные для них варианты ассета;
- favicon, структурированные данные, шапка и подвал должны ссылаться на актуальную айдентику согласованно.

## 5. Фотостиль

Фотографии — главный эмоциональный слой сайта.

- приоритет реальным фотографиям курорта, детей в деятельности, команды, помещений и природы;
- показывать безопасные, естественные ситуации и живые эмоции без чрезмерной постановочности;
- избегать тяжёлых фильтров, клипарта и смешения разных фотостилей в одной секции;
- карточки одного ряда получают одинаковое соотношение сторон;
- для фоновых изображений использовать `cover`, для документов, схем и предметных изображений — `contain`;
- не размещать важные лица и текст близко к зоне обрезки;
- текст поверх фотографии допускается только при стабильном контрасте и затемняющем overlay;
- у содержательных изображений должен быть информативный `alt`; у декоративных — пустой `alt=""`.

## 6. Иконки

- использовать единый набор простых линейных или компактных заливных SVG-иконок;
- типовые размеры: 16, 20, 24 px; в самостоятельной икон-кнопке — до 44 px зона нажатия;
- толщина линий и характер углов должны быть одинаковыми внутри одной группы;
- эмодзи допустимы только как редкий эмоциональный акцент, не как системная навигация;
- иконка без подписи разрешена только для общеизвестного действия и должна иметь доступное имя.

## 7. Компоненты

### Кнопки

Иерархия:

1. `btn-primary` — одно главное действие: оставить заявку, забронировать, связаться.
2. `btn-secondary` / `btn-soft` — альтернативное или поясняющее действие.
3. `btn-ghost` — малоприоритетное действие на спокойном фоне.

Правила:

- текст начинается с глагола: «Выбрать смену», «Оставить заявку», «Скачать памятку»;
- в одном смысловом блоке обычно одна primary-кнопка;
- минимальная высота интерактивной зоны — 44 px;
- не переносить короткую подпись кнопки на две строки; на узком экране лучше сделать кнопку шире;
- hover слегка поднимает элемент, active возвращает его на поверхность;
- disabled-состояние должно визуально отличаться и не реагировать на наведение;
- внешняя ссылка или файл по возможности обозначаются соответствующей иконкой или уточнением.

### Ссылки

В тексте ссылка должна отличаться не только цветом: использовать подчёркивание или явный контекст. Телефоны, email и адреса оформляются настоящими ссылками. Не маскировать ссылку под обычный текст.

### Карточки

Карточка объединяет один объект или одну задачу. Базовая структура: изображение → метаданные → заголовок → описание → действие.

- не вкладывать полноценную карточку в карточку;
- карточки одной группы имеют одинаковую внутреннюю структуру и сопоставимую высоту;
- вся карточка кликабельна только если у неё одно действие;
- hover применяется только к интерактивной карточке;
- важные цена и даты не должны быть спрятаны в модальном окне.

### Метки, badges, pills

Метка описывает короткий атрибут: возраст, длительность, сезон, статус. Это не кнопка, если по нажатию ничего не происходит. Текст — 1–3 слова; несколько цветов вводятся только при устойчивой семантике.

### Вкладки

Использовать для переключения равноправных представлений внутри одной области. Активная вкладка имеет `aria-selected="true"`, связана со своей панелью и доступна с клавиатуры. Не применять вкладки вместо обычной навигации между страницами.

### Формы

- постоянная подпись располагается над полем; placeholder не заменяет label;
- обязательность и формат объясняются до отправки;
- ошибка показывается рядом с полем, текстом и визуальным состоянием;
- введённые корректные данные не стираются после ошибки;
- чекбокс согласия не включён заранее;
- после успешной отправки показывается ясное подтверждение и следующий шаг;
- поля и кнопки сохраняют видимый `focus-visible`.

### Модальные окна

Используются для короткого сфокусированного сценария, а не для длинной самостоятельной страницы. Обязательны: понятный заголовок, видимая кнопка закрытия, закрытие по `Escape`, удержание фокуса внутри, возврат фокуса инициатору и блокировка прокрутки фона.

### FAQ

Использовать нативные `details/summary`. Вопрос формулируется как реальный вопрос пользователя, ответ начинается с прямого вывода. Не скрывать в FAQ критичные условия покупки.

### Шапка и подвал

Шапка содержит логотип, основные разделы и один главный CTA. На экранах до 1180 px основная навигация заменяется мобильной. Подвал повторяет ключевые контакты, юридическую информацию, документы и навигацию, но не превращается во вторую главную страницу.

## 8. Композиция страниц

Рекомендуемый порядок посадочной страницы:

1. первый экран: предложение, ключевая польза, CTA и эмоциональное фото;
2. доверие: факты о курорте, безопасность, инфраструктура;
3. продукт: смены, программы, цены и даты;
4. подтверждение: команда, медицина, отзывы, документы, фотографии;
5. снятие возражений: FAQ и информация для родителей;
6. контакт и финальный CTA;
7. маршрут, способы оплаты и подвал.

Каждая секция отвечает на один вопрос пользователя. Заголовок сообщает вывод, подзаголовок уточняет, контент доказывает, CTA предлагает следующий шаг.

## 9. Адаптивность

Рабочие контрольные точки текущей системы:

- до `1280px` — уплотнение desktop-навигации;
- до `1180px` — переход к мобильной навигации;
- до `1024px` — сложные сетки переходят к 1–2 колонкам;
- до `768px` — основной мобильный сценарий;
- до `420px` — компактные поля и одноколоночная раскладка.

Правила:

- проектировать сначала смысловой порядок, затем количество колонок;
- горизонтальный скролл допустим для карусели карточек, но не для страницы целиком;
- важный контент не исчезает на мобильном, допускается только изменение порядка;
- зона нажатия не меньше 44×44 px, расстояние между соседними действиями — не меньше 8 px;
- проверять ширины 320, 375, 768, 1024, 1280 и 1440 px;
- не привязывать высоту текстовой карточки к жёсткому значению, если контент может измениться.

## 10. Доступность

Целевой уровень — WCAG 2.2 AA.

- контраст обычного текста не ниже 4.5:1, крупного — 3:1;
- интерфейс полностью управляется клавиатурой;
- фокус видим и не перекрыт sticky-шапкой;
- у страницы есть логичная структура landmark-областей и заголовков;
- `aria-label` дополняет семантику, а не заменяет видимый текст без необходимости;
- анимации отключаются при `prefers-reduced-motion: reduce`;
- видео не запускается со звуком автоматически;
- ошибки, статусы и открытие модальных окон объявляются вспомогательным технологиям;
- язык документа задаётся через `lang="ru"`.

## 11. Motion

Движение короткое и функциональное:

- быстрый переход: `160ms`;
- спокойный переход: `260ms`;
- easing: `cubic-bezier(.2,.9,.2,1)`;
- hover-подъём: 1–4 px в зависимости от размера элемента;
- не анимировать большие объёмы текста и не использовать бесконечные декоративные циклы;
- при reduced motion отключать переходы и плавную прокрутку.

## 12. Тон коммуникации

Пишем для родителей ясно и по-человечески.

- сначала конкретика: что, для кого, когда, сколько стоит и что входит;
- короткие предложения и активный залог;
- без необоснованных превосходных степеней и давления;
- официальные термины поясняются обычными словами;
- название, цены, даты, возраст и телефон пишутся одинаково во всех местах;
- CTA обещает именно то, что произойдёт после нажатия.

Пример: «Оставьте номер — администратор уточнит наличие мест и ответит на вопросы» лучше, чем «Узнать больше».

## 13. Архитектура CSS

Текущая система разделена по ответственности:

- `styles/tokens.css` — токены;
- `styles/base.css` — reset, базовая типографика, контейнер;
- `styles/layout.css` — каркас страницы и крупные раскладки;
- `styles/components.css` — переиспользуемые компоненты и состояния;
- `styles/sections.css` — уникальные секции;
- `styles/responsive.css` — адаптивные изменения.

Правила разработки:

- сначала переиспользовать существующий компонент, затем добавлять модификатор;
- не использовать inline-стили для постоянного оформления;
- не привязывать общий компонент к ID конкретной секции;
- состояние именовать явно: `is-open`, `is-active`, `is-loading`, `has-error`;
- селекторы держать короткими, избегать `!important` и глубокой вложенности;
- значения из утверждённой шкалы выносить в токены при повторном использовании;
- скрытие через `hidden` должно оставаться семантически согласованным с JS и ARIA.

## 14. Контроль качества перед публикацией

### Визуальная проверка

- использованы утверждённые цвета, шрифт, радиусы и интервалы;
- на экране нет конкурирующих primary-действий;
- сетка и вертикальные отступы последовательны;
- фотографии качественные и кадрируются предсказуемо;
- hover, focus, active, disabled, loading, error и success учтены там, где применимо.

### Контент и поведение

- цены, даты, возраст, контакты и названия сверены с источником данных;
- ссылки, телефоны, email, скачивание и формы работают;
- интерактивные элементы имеют понятные названия;
- модальные окна и меню закрываются с клавиатуры;
- нет скрытого важного контента или тупикового сценария.

### Адаптивность и техника

- проверены ключевые ширины и отсутствие горизонтального скролла страницы;
- изображения имеют корректные размеры, `alt` и не вызывают заметного layout shift;
- проверены консоль браузера, валидность HTML и базовый Lighthouse-аудит;
- анимация корректно отключается настройкой reduced motion.

## 15. Правило развития системы

Новый компонент добавляется только если существующий нельзя расширить без потери смысла. Для добавления фиксируются:

1. задача и сценарий использования;
2. анатомия компонента;
3. варианты и размеры;
4. состояния и поведение;
5. адаптивность;
6. требования доступности;
7. пример разметки и место CSS-реализации.

Изменения токенов и базовых компонентов проверяются минимум на главной странице и странице сведений. Разовые рекламные страницы также используют эту основу; отдельная визуальная тема допустима только как документированное расширение, а не как параллельная система.

## 16. Зафиксированные продуктовые решения

По состоянию на версию 1.1 приняты следующие решения:

1. **Красный — главный цвет CTA.** Основные действия оформляются красным градиентом системы. На одном экране не должно быть нескольких конкурирующих красных действий.
2. **`camp-landing.html` — действующая страница.** На неё распространяется этот Design System. При плановых изменениях страницу следует постепенно привести к Montserrat, общей палитре, токенам и компонентам, не нарушая текущую работу.
3. **Отдельного детского визуального режима пока нет.** Все страницы используют единую спокойную основу, ориентированную прежде всего на родителей. Детская энергия передаётся фотографиями, содержанием и дозированными акцентами.
4. **Официального брендбука пока нет.** До его появления обязательными считаются правила раздела «Логотип и айдентика» этого документа. После получения брендбука его требования к логотипу имеют приоритет и должны быть перенесены в Design System.

Эти решения действуют для всей дальнейшей разработки, пока не будут пересмотрены в новой версии документа.
